# architecture
- MANTrixFlow uses DuckDB-staged ELT: source → dlt → ephemeral DuckDB → dbt-duckdb transforms → delivery to client destination. No raw _dlt_* tables land in client DB. Confidence: 0.90
- dbt models are authored exclusively via inline UI SQL editor (Monaco). No GitHub dbt projects, no Meltano. Confidence: 0.85
- Sync mode and replication key belong to the destination node, not the source node. Source panel owns only stream selection and connection. Confidence: 0.80
- Pipeline builder model: one source node feeds multiple plain destination nodes via direct edges. No branch/groups concept. Plus icon on source adds a destination. Confidence: 0.75
- All schema.table references use a single string input format (e.g., "public.users"), not separate schema and table fields. Parse by splitting on first dot. Confidence: 0.65
- Destination delivery writes into existing tables only. Never create new tables in client destinations. If destination table does not exist, fail with clear error. Confidence: 0.65
- When adding a new SQL/warehouse connector (ClickHouse, Snowflake, Redshift, DuckDB, etc.), never build a parallel `*_special_pipeline` / `*_custom_runner` / `*_source_server` / `*_destination_loader`. Reuse the generic SQL connection model, discovery, preview, source pipeline, destination pipeline, dlt staging, dbt transformations, credential encryption, organization isolation, and pipeline validation. Add only the new connector's truly connector-specific adapter logic (e.g., SQLAlchemy dialect registration, native driver choice). Confidence: 0.90
- Server connector capability (Go `connectorCapabilities`) is authoritative for security and backend routing. Frontend `sourceCapable` / `destCapable` flags are UX hints, not a security boundary. Never rely on frontend capability for routing decisions. Confidence: 0.85
- Connector product identity uses the canonical lower-case ID everywhere (e.g., `clickhouse`, never `clickhousedb` / `click_house` / `clickhouse-source` / `clickhouse-destination` / `ch` for product UI/routing/registry). Aliases are acceptable for input normalization only — the canonical ID is the single source of truth. Confidence: 0.85
- A single connection contract is reused across source, destination, and test-connection roles when the underlying system supports both directions (subject to per-role server permission checks). Never produce three different credential shapes for source / destination / test. Confidence: 0.80
- Connector production READY requires an executed end-to-end row movement against the real target system, not just imports, `SELECT 1`, or mock tests. Cross-connector E2E (e.g., A→B, B→A, A→A) with seeded representative data is the explicit gate for marking a connector production-ready. Confidence: 0.85
- Secret-redaction testing must include a unique sentinel string (e.g., `CLICKHOUSE_SECRET_NEVER_LEAK_8737`) and assert that the sentinel never appears in HTTP responses, browser logs, Go logs, Python logs, SSE events, audit envelopes, agent/tool calls, or destination object `__repr__`. Use the existing platform scrubber as the single source of truth and write explicit tests asserting scrubber coverage of new URL builders / DSNs. Confidence: 0.85
