## CRITICAL Issues (Must Fix Before Production)

### 1. `service_role` JWT in Frontend .env — .env
```
service_role=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```
The Supabase **service_role key** is in the frontend .env. While it's gitignored and not prefixed with `NEXT_PUBLIC_`, it's still sitting alongside client-side env vars. If accidentally referenced client-side or leaked, it grants **full admin access** bypassing RLS.

**Fix:** Remove from .env. Move to server-side-only env config (Go API already loads its own).

### 2. `ANTHROPIC_API_KEY` Placeholder in Frontend .env — .env
```
ANTHROPIC_API_KEY=your_anthropic_api_key_here
```
API keys for external services should never live in the frontend project. Even if it's a placeholder, when replaced with a real key it's at risk.

**Fix:** Move to Go API server env only.

### 3. ETL .env — Same Token for Everything — .env
```
ENCRYPTION_KEY=uajhxhxMPexfahZI2HbpIvgALaht9QTF
ETL_INTERNAL_TOKEN="uajhxhxMPexfahZI2HbpIvgALaht9QTF"
CALLBACK_TOKEN="uajhxhxMPexfahZI2HbpIvgALaht9QTF"
```
All three secrets use the **same value**. If one leaks, all internal auth is compromised.

**Fix:** Generate unique tokens for each: `openssl rand -hex 32` per token.

### 4. No Rate Limiting — Go API
No rate limiting anywhere in the Go API. Any authenticated user can flood the API, triggering unlimited ETL pipeline runs.

**Fix:** Add `fiber/middleware/limiter`:
```go
app.Use(limiter.New(limiter.Config{
    Max:        100,
    Expiration: 1 * time.Minute,
}))
```

### 5. `exec()` for User Transform Scripts — transform_handler.py
```python
exec(script, namespace)  # User-provided Python code
```
User-provided Python code is executed via `exec()` with no sandboxing. This allows arbitrary code execution on the ETL server (file system access, network calls, credential theft from env vars).

**Fix:** Run transforms in a sandboxed subprocess with restricted imports, or use a safe expression evaluator. At minimum, restrict `namespace` builtins:
```python
namespace = {"__builtins__": {}}  # Strip dangerous builtins
```

## HIGH Issues (Address Soon)

### 6. CORS Defaults to `*` in Production — config.go
```go
if strings.EqualFold(c.Environment, "production") {
    return "*"
}
```
When `CORS_ALLOWED_ORIGINS` is not set, production defaults to allow **all origins**.

**Fix:** Default to empty/specific origins in production, require explicit configuration.

### 7. No Security Headers — Next.js App
next.config.ts only has CSP for SVG images. Missing:
- `X-Frame-Options: DENY` (clickjacking protection)
- `X-Content-Type-Options: nosniff`
- `Strict-Transport-Security` (HSTS)
- `Referrer-Policy`
- Full `Content-Security-Policy`

**Fix:** Add headers in next.config.ts:
```typescript
async headers() {
  return [{
    source: "/(.*)",
    headers: [
      { key: "X-Frame-Options", value: "DENY" },
      { key: "X-Content-Type-Options", value: "nosniff" },
      { key: "Strict-Transport-Security", value: "max-age=31536000; includeSubDomains" },
      { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
    ],
  }];
}
```

### 8. Internal Token Has No Expiration/Rotation
The `X-Callback-Token` / `X-Internal-Token` is a static string comparison with no expiration, no rotation mechanism, and no HMAC signature.

**Fix:** Implement time-based tokens (HMAC with timestamp) or use short-lived JWTs for internal service auth.

### 9. Token Fallback Chain — config.go
```go
ETLInternalToken: firstNonEmpty(os.Getenv("ETL_INTERNAL_TOKEN"), os.Getenv("INTERNAL_TOKEN"), os.Getenv("SUPABASE_SERVICE_ROLE_KEY"))
```
Falls back to `SUPABASE_SERVICE_ROLE_KEY` if no internal token is set. This means the Supabase admin key could be used as an internal service token — dangerous scope mixing.

**Fix:** Remove `SUPABASE_SERVICE_ROLE_KEY` from the fallback chain. Require explicit internal tokens.

### 10. Query Results in sessionStorage — page.tsx
```typescript
sessionStorage.getItem(`query-results-${dataSourceId}`)
sessionStorage.setItem(`query-results-${dataSourceId}`, ...)
```
Database query results (potentially sensitive) are stored in plaintext `sessionStorage`. Accessible via JS (XSS risk) and persists for the browser session.

**Fix:** Keep query results in React state only. Don't persist to browser storage.

### 14. No CSRF Protection

### 15. ENCRYPTION_MASTER_KEY Rotation
No mechanism exists to rotate the encryption key. All stored credentials would need re-encryption with a new key. Should implement key versioning (store key version with encrypted data).
